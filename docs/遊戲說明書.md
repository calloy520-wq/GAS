# 《廢村開拓》設計說明書

> 這是一個**全新的遊戲**，與前一個專案《海與劍之歌》沒有任何關係。
> 舊遊戲的完整程式碼保留在 git 歷史中（最後一版為 commit `56526e7`），隨時可取回。

---

## 0. 一句話

你帶著三個人走進一座荒廢的村子，每天給每個人派一份工，撐過第一個冬天。

**類型**：小隊生存模擬（《無人島物語》×《牧場物語》）
**平台**：Google Apps Script 網頁，手機可玩
**玩法**：回合制、純文字＋數值，無即時操作

---

## 1. 核心鐵律（動工前必讀）

> **所有數值、成敗、生死都在 `Engine.html` 裡算完。文字永遠只是文字。**

玩家可以自由打字下指令，但**能決定的只有「下什麼指令」，不能決定「指令的後果」**。
流程固定為四段，AI 排在最後一站而且唯讀：

```
玩家輸入
  ↓
① 意圖解析   自由文字 → 壓成合法指令（只能從固定清單選）
  ↓
② 驗證       程式碼檢查：指令合法？資源夠？這個人有空？→ 不合法當場擋掉
  ↓
③ 結算       純程式碼算結果（骰子、消耗、成敗、傷亡）★唯一能改數值的地方★
  ↓
④ 敘事       只拿「算完的結果」寫成文字（目前為模板，之後接 AI）
```

所以：
- 「我用魔法變出一百袋米」→ 歸類為荒謬，世界用文字回應，**資源一格不動**
- 「我一個人一天蓋好一棟房子」→ 指令合法，但進度由程式算，寫得再熱血也只 +3%
- 「阿福其實沒死」→ 生死在存檔裡，AI 說什麼都不影響
- 全員死亡＝結束，開新局，不留情

**之後接 AI 時，這條鐵律不能破**：AI 只收 `report` 物件，回傳純文字，不得回寫任何欄位。
因此 AI 掛掉時遊戲永遠是完整可玩的（模板保底）。

## 2. 檔案分工

| 檔案 | 職責 |
|---|---|
| `Data.html` | 純資料表：季節／天氣／個性／工作／建築／地點／事件／姓名／平衡常數 `C` |
| `Engine.html` | 結算引擎（純函式）：`newRun` / `ensureShape` / `resolveDay` / `startBuild` / `narrate` |
| `Index.html` | 前端 SPA：畫面、派工介面、指令解析、面板。用 `<?!= include('Data') ?>` 引入上兩者 |
| `Code.gs` | `doGet` ＋ `api()` 路由：`load` / `save` / `ruins` / `bury` / `narrate` / `meta` |
| `Store.gs` | Sheet 資料層：存檔、廢墟、快取。Script Property key `VILLAGE_SHEET_ID` |

### 架構決定：引擎放前端，只有一份

前一個專案最大的維護痛點是「伺服器邏輯」與「前端離線 mock」必須手動同步兩份，
每次改規則都可能不一致。本專案**刻意不這樣做**：

| 東西 | 放哪 | 理由 |
|---|---|---|
| 遊戲引擎 | **前端，單一份** | 不需要鏡像，永久消滅同步雷區；操作 0 延遲 |
| 存檔 | 伺服器 Sheet | 跨裝置、不會丟 |
| AI 敘事 | **伺服器** | API key 絕對不能出現在前端 |

代價：前端可被改值作弊。目前是單人遊戲，作弊只影響自己，可接受。
**若日後加入排行榜或真正的 PvP，必須把 `resolveDay` 搬到伺服器並改回權威模式。**

引擎是純函式且不呼叫任何 Google API，所以可以直接拉進 Node 跑模擬：
```bash
node sim.js 300 80        # 300 局平衡模擬
node autosim.js 300       # 在瀏覽器裡跑真前端的「自動模式」
```

## 3. 遊戲循環

```
早上  看村落狀態（資源／天氣／每個人的體力心情健康）
派工  每人指派一份工作（可手動點、可打字、可按「自動」、可「同昨天」）
過天  結算 → 當日報告 → 寫進村誌
```

一季 20 天，一年 80 天（`SEASON_LEN` / `WIN_DAY`）。**撐到第 80 天＝站住腳**，
會跳里程碑畫面，玩家可選擇「繼續經營」或「就此收尾」。

## 4. 系統

### 4.1 工作（`JOBS`）
採集／狩獵／取水／伐木／採石／農耕／建造／踏查／照護／休息。

產出公式（`workPower`）：
```
出力 = 基準 × 技能 × 個性 × 體力 × 心情 × 季節 × 天氣 × 地點 × 隨機
```
- 技能 1.0→5.0，做哪種工練哪種，有邊際遞減（`SKILL_GAIN`）
- 體力低於 `STAM_LOW`(30) 產出打折；帶病工作每級 −22%
- 狩獵波動最大（`vary` 0.55），可能空手而回，也可能受傷

### 4.2 個性（`TRAITS`）
14 種，**每一種都真的動數值**，不是只有文字：耐勞（體力消耗 ×0.78）、
綠手指（採集農耕 ×1.3）、獵戶（狩獵 ×1.45 且不易受傷）、貪婪（可能私藏糧食）、
體弱（生病率 ×1.65）、剛硬（不易動搖）……

### 4.3 建築（`BUILDS`）
住所／水井／農田／倉庫／療養所／柵欄，各 2-3 級。
開工時一次扣材料，之後靠派人「建造」累積工數；停工退回一半材料。

- **住所**：人口上限、降生病率、提升心情
- **水井**：每日自動湧水（`C.WELL_YIELD = [0, 9, 22]`，只打到裝得下的量）
- **倉庫**：資源上限 ×1.8/級，並減緩糧食腐壞
- **柵欄**：擋野獸；蓋滿 2 級後野獸事件完全不會發生

### 4.4 生存壓力
每人每天吃 1 糧、喝 1 水（夏季 ×1.5），**冬天每人每天燒 1 柴**。
缺乏時扣血：渴 22 ＞ 餓 13 ＞ 冷 11（帶 ±35% 浮動，讓倒下有先後、玩家來得及搶救）。

**冬天是設計上的那道牆**：採集 ×0.35、農耕為 0、生病率 ×1.8、還要燒柴。
唯一解法是在秋天之前囤夠糧和柴。模擬顯示滅村有約一半發生在第 70-80 天，符合意圖。

### 4.5 地圖（`SPOTS`）
派人踏查累積進度，到門檻解鎖地點，提供永久加成：
淺溪（取水 ×1.3）→ 野果林 → 黏土坡 → 獸徑 → 藥草窪地 → 舊屋遺構（一次性物資）
→ 荒廢祠堂（每日心情回升）→ 山口小徑（開放商旅事件）。

### 4.6 事件（`EVENTS`）
每天 55% 機率觸發，**全部由程式抽選**：野獸來襲、有人病倒、口角爭執、屋舍受損、
糧食短少、**有人來投**（角色收集）、意外收穫、情誼漸生、商旅經過、平靜的一天。

條件會過濾事件池（例：柵欄滿級不會有野獸、人滿了不會有人來投、
沒有貪婪個性的人就不會有偷糧）。

### 4.7 結局（`ENDINGS`）
- `wipe` 村落斷絕——最後一人倒下
- `flee` 人去樓空——所有人心情崩潰離開
- `thrive` 炊煙不絕——撐過第 80 天

### 4.8 廢墟（非同步多人的第一步）
滅村的村子會寫進 `Ruins` 分頁，附上最後一篇村誌。
別的玩家在結局畫面可以翻看別人的廢墟。單人完整可玩，但世界裡有別人的故事。

> 只有 `wipe` / `flee` 會變成廢墟；活下來的村子不會被埋。

## 5. 自由打字指令

三段式處理，**不擋創意，但也不讓文字改變數值**：

| 玩家輸入 | 處理 |
|---|---|
| 「叫阿福去砍柴」「大家休息」「蓋水井」 | ① 對應合法指令 → 照做 |
| 「垂降到懸崖下看看」「下水摸魚」「掏蜂巢」 | ② 說得通但不在選單 → 進入判定：高體力消耗、有受傷機率、有額外收穫（`RISKY` 表） |
| 「我用魔法變出一百袋米」 | ③ 物理上不可能 → 世界用文字回應，數值一格不動（`ABSURD` 表） |

`RISKY` 的後果一律由 `workPower` 算，所以「天馬行空」真的會有結果，但結果是預先定好的。

## 6. UX 決定（都是為了不累）

| 問題 | 做法 |
|---|---|
| 不想天天重設派工 | 開檔時自動回填上次派工；另有「↻ 同昨天」 |
| 不想一天一天點 | 「⏩ 連過」一次最多 5 天，**一有狀況（死亡／出走／警告／有人來投／里程碑）就自動停下** |
| 不知道該派誰做什麼 | 「⚙ 自動」會自己開工程＋派工（模擬 300 局滅村率 21%，不會按了就死） |
| 看不出資源夠不夠 | 資源列顯示 `現有/上限`，低於兩天用量時變紅，滑過顯示每日消耗 |
| 不知道工作能不能做 | 不可用的工作變灰，滑過顯示原因（「冬天沒有收成」「病得太重」） |

## 7. 平衡基準（改動後請重跑）

以 `autosim.js` 300 局（前端自動模式，80 天）為基準：

| 指標 | 目標值 | 目前 |
|---|---|---|
| 滅村率 | 15-30% | 21.3% |
| 滅村高峰 | 第 70-80 天（冬天） | ✅ 約半數 |
| 平均完成工程 | 7-11 | 9.0 |
| 平均損失人口 | 1-3 | 1.9 |
| 平均存活人口 | 4-7 | 5.7 |

滅村率低於 15% 代表太簡單（冬天不再是牆）；高於 30% 代表懲罰過重。

## 8. 待做（Phase 2 起）

1. **接 AI 敘事**：`apiNarrate_` 用 `UrlFetchApp` 呼叫 LLM，輸入只有 `report` ＋角色人設卡，
   輸出純文字。記憶靠「狀態 + 大事記 + 近期原文」三層，不送對話歷史，成本才會是固定的。
   金鑰用 `setAiKey()` 存進 Script Properties，不進 git。
2. **意圖解析改用結構化輸出**：目前是關鍵字比對，可改成讓 LLM 只能吐固定 enum 的分類器
   （類型／對象／風險／目標），後果仍然查表決定。
3. **廢墟深化**：踏查時真的挖到別人的廢墟並取得物資。
4. **季節深化**：節慶、作物品種、動物養殖。
5. **村子長大之後**：商隊、鄰村（其他玩家）、外部勢力——妳原本想要的經營／權謀那一層。

## 附錄：存檔結構

```js
{
  nick, ver,
  run:   { seed, seed0, day, weather, over, ending, overDay },
  res:   { food, water, wood, stone, herb, coin },
  people:[ { id, name, sex, age, trait, skills{gather,labor,hunt,heal,scout},
             stam, mood, hp, sick, job, bonds, days, alive } ],
  build: { shelter, well, farm, store, infirm, wall },   // key → 完成等級
  site:  { key, lv, work, need } | null,                 // 進行中的工程
  map:   { explored, found[] },
  log:   [ { day, season, weather, text } ],             // 最近 60 天
  stats: { lost, joined, built, bestDay }
}
```

亂數狀態存在 `run.seed`，整局可由 `seed0` ＋操作序列完整重播——
之後要做廢墟重現或戰報回放時會用到。

改存檔欄位時**務必同步 `ensureShape()`**（`Engine.html`），否則舊存檔讀進來會缺欄位。
